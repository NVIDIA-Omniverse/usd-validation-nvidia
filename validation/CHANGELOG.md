# Changelog

## [1.21.0] - 2026-08-12
### Added
- Add `UsdGeomSubsetFamiliesChecker` and `UsdGeomSubsetParentIsImageableChecker` rules, wrapping the current OpenUSD
  `usdGeomValidators:SubsetFamilies` and `usdGeomValidators:SubsetParentIsImageable` validators with Python fallbacks.
- Validation identifiers and layer compliance events can now be pickled and restored, enabling validation work to cross
  process boundaries safely.
- Rule methods can now be marked with `@multiprocess_safe` so process-based runners can identify callbacks that are
  safe to execute outside the parent process.
- Experimental process-based validation can now run `LayerSpecChecker` through
  `ValidationEngine(processes=...)` and the CLI `--process COUNT` option.
- The repository is now a `uv` workspace that builds two wheels from the same commit and the
  shared `VERSION.md`: `usd-validation-nvidia` (root) and `usd-profiles-nvidia` (`profiles/`
  member, placeholder until the code migration lands). One source repository per NSPECT
  release, multiple published artifacts.
- Rules can now register requirement references that resolve when the required package is available.
- The `usd-profiles-nvidia` package is now developed in this repository (`profiles/` workspace
  member, migrated from the standalone usd-profiles-nvidia repository at v1.16.0). Both wheels
  build from the same commit and the shared `VERSION.md`, so `usd-profiles-nvidia` continues
  from this repository's version line.

### Changed
- CSV validation reports now stream row-backed data directly to disk, reducing peak memory use for large
  validation result sets.
- JSON validation reports now write `IssueJSONEncoder.iterencode()` chunks instead of materializing the
  complete encoded payload before writing.
- Frequently recreated immutable validation identifiers and suggestions are now deduplicated with a bounded
  cache, reducing duplicate object churn during large validations.
- Suggestion fix callbacks now avoid per-issue bound and partial callables, allowing equivalent
  `Suggestion` objects from repeated validation failures to be deduplicated more effectively.
- Validation source, docs, examples, and tests now live under the `validation/` workspace member.
- Documentation links, package positioning, license notices, and build tooling were refreshed.

### Fixed
- The CLI now defaults to warnings and errors while keeping validation issue summaries visible when issues are found.
  Use `-v` for informational logs and `-vv` for debug logs.
- `HierarchyHasRootChecker` (HI.001) now reports scattered root prims accurately and ignores helper roots that are not
  part of the referenceable asset.
- JSON reports now serialize stage paths from root layer identifiers, avoiding deprecated `StageId.identifier` access.
- USDZ texture validation now accepts `jpg`, `jpeg`, `png`, and `exr` extensions correctly.

## [1.20.0] - 2026-07-01
### Added
- Add `ValidationEngine(instance_prototypes=False)` and CLI `--no-instance-prototypes` support to skip instance proxy
  prim traversal on heavily instanced stages.
- Add Installation, Authoring, and Migration documentation covering package setup, custom rule authoring, auto-fix usage,
  native USD validator wrapping, plugin entry points, and `omni.asset_validator` migration guidance.
- Add runtime rule skip conditions with `skip_if`, `skip_unless`, `RulePredicates`, and `is_importable`.
  Rules whose conditions match remain registered but are not instantiated or run; validation reports an `INFO` issue
  such as `Skipping rule RuleConditionSkippedRule: Missing test rule support.`
- `Feature` objects now include a `dependencies` field. For example,
  `Features.MINIMAL_PLACEABLE_VISUAL.dependencies` returns that feature's dependency list, currently empty; feature,
  profile, engine, and validation context requirement resolution includes requirements from those dependencies.
- Features can now include `RequirementRef` placeholders. If a feature references a fully namespaced requirement code
  that cannot be resolved in the current registry, the reference is preserved so it can resolve later at runtime.

### Changed
- Update all agent skills to remove legacy `omniverse-usd-profiles` fallback guidance and use the now-public
  `usd-profiles-nvidia` package instead.
- All requirements, capabilities, and features in `usd-validation-nvidia` now use the `com.nvidia.usd` prefix.
  CLI options that accept these identifiers now require the full identifier, for example
  `com.nvidia.usd.AA.001` instead of `AA.001`.
- `register_requirements`, used to register a `BaseRuleChecker` in the requirements registry, now requires concrete
  `Requirement` objects generated by `usd-profiles-nvidia`. Partial or mock requirements with only `code`, `version`,
  and `message` now raise `TypeError: register_requirements expects concrete Requirement objects.`

### Fixed
- Normal-map validation now reports non-raw texture color spaces and offers an automatic fix that authors
  `sourceColorSpace = "raw"` plus the canonical 8-bit normal-map scale and bias from the UsdPreviewSurface specification.
- Skip normals winding validation for malformed normals topology so dedicated normals and primvar rules report those
  issues.
- Resolve relative root asset paths before dependency computation so `MissingReferenceChecker` no longer reports
  false unresolved external dependencies for valid relative sublayers.
- `ValidationEngine` now returns an `ERROR` issue when an enabled requirement has no registered `BaseRuleChecker`.
  For example, enabling `com.nvidia.usd.VG.003` (`usdgeom-mesh-internal-geometry`) without the implementing package
  installed reports `Requirement (com.nvidia.usd.VG.003, 1.0.0) has not been implemented`.
- Unresolved `RequirementRef` placeholders now surface as validation errors instead of disappearing from results. For
  example, if no package registers `com.nvidia.usd.VG.003`, validation reports
  `Requirement (com.nvidia.usd.VG.003, 1.0.0) has not been implemented`; if it is registered later, its rule runs.
- Versioned registries now support deleting a specific entry with `del registry[key]`; use `clear()` only when every
  entry should be removed. `RequirementsRegistry` also cleans up rule-to-requirement mappings for the deleted key.
